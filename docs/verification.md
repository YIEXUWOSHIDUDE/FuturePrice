## 拼多多 OCR 漏标修复（同日后续）

用户随后授权 CC 修改，并明确本轮只修 OCR、暂不开发直读。CC 使用 Opus 5.5 修改产品，Codex 独立复现、审查、构建及模拟器验证。

修复前用测试 APK 的 `mode=live -e min_tags 4` 在同一真实游客页连续两次复现失败：4 条价格/销量合行，产品引擎输出 0 个标签。截图只在测试进程内存处理，输出只有包名和聚合计数。合成 `sales_fixture` 也复现 4 个正例全漏、3 个负例正确拒绝。

根因与修改：

- ML Kit 将主价和 `Store sales:` 并成整行，且把小号 ¥ 读作 y；严格整行价格解析因此拒绝。现在只拆分完整匹配已知销量后缀的行，价格坐标来自 Element；误读的币种在有限原图区域内定位完整字形，并通过既有双横线/分叉/竖干检查。真正 Y 不直接转成币种，PriceRules 和 YenGlyph 的阈值未放宽。
- Symbol 框会裁掉实际 ¥ 笔画，不能直接当作完整字形裁剪框；最终价格 source 并入像素确认的币种框。
- 识别恢复到 4 个后，另 2 个标签因原 24dp 高度与下一排 OCR 文字框重叠约 4px 被拒。维持 14sp 字号，依次尝试正常布局、紧凑高度、紧凑高度加较小间距，全部仍执行屏幕/文字/标签碰撞检查。保留不同间距是为了同时避开同行较低的销量文字和下一排文字。
- 另一真实页的销量 `5M` 暴露后缀覆盖缺口，补入 M/m；销量单位不参与金额计算。

最终运行 `scripts/verify-android.sh --offline` 成功：12 个 JUnit 测试无失败、Lint 无错误、Debug/Release 构建及禁止权限检查通过。`scripts/verify-ocr-snapshots.sh --offline` 全部通过：原两张截图分别 4/1 个预期标签；普通与紧凑 `sales_fixture` 各 4 个正确标签，券后、区间、真正 Y 三种负例均拒绝。合成正例覆盖 K、M、无单位和 K+ 销量。

## 真实 AccessibilityService 直读可行性实验（2026-10-06 后续）

用户授权「测吧」。CC（实际 Claude Code Opus 5.5）实现独立 `:directprobe` 模块，Codex 审查并在原 Android 15 ARM64 模拟器上操作验证。包名 `dev.futureprice.directprobe`，没有复用 UiAutomation 读取；启用真实无障碍服务后不使用 UIAutomator，避免抑制普通无障碍服务影响结果。实验开启 `canRetrieveWindowContent`，不声明截图、手势、网络或 MediaProjection 能力，也不伪装为 `isAccessibilityTool`。产品 app 与 fixture 的 11 个原有源码/资源文件 SHA-256 前后逐一相同；产品 APK 未替换。

实验框只标出价格节点、编号与固定 1.5 倍计算结果，不做商品主价归属或标签避让，不能作为产品贴标通过。手机画面由 adb 单次截图供人工核对，实验应用本身不截图，临时真实游客页截图核对后删除。全过程未登录、未同意购物 App 隐私条款。开始、中途、结束检查 `dumpsys media_projection` 均为 null。

### 实验工具修正与对照

1. 超时只标记结果过期，真实后台调用返回前保留 busy；后续请求最多合并一个，不因超时继续向单线程队列堆任务。完成的超时/过期读取也计入实际耗时，避免只统计快调用。没有假定 Binder 可以取消。
2. 初版按祖先框裁切并提前剪掉子树，实测造成漏读。最终版遍历全部节点（上限 2000），同时统计 strict（要求祖先框包含）与 flat（仅自身正常屏内框、可见标记、跨窗口遮挡等过滤）；切换命令只改变诊断显示。
3. `event_to_clear_request_ms` 仅计事件时间到请求 View 重绘清框；不是屏幕实际撤标延迟。没有测得可作为验收的端到端 P95。

最终版进程 17984 的目标包读取（含超时、过期、窗口尚未就绪的拒绝，不含其它系统/桌面读取）：淘宝 11 次，2–1840ms，3 次 timeout；拼多多 8 次，14–1417ms，2 次 timeout；fixture 3 次，96–568ms。每次包含 root/窗口取得与节点遍历。最终淘宝某个样本的严格过滤并未减少遍历，所以不能按不同候选数推导耗电。早期剪枝版还出现过拼多多 2175ms 长尾，和最终版不是同一遍历范围，不能直接算性能提升。

样本含缓存、切换与系统事件，数量很少；没有与 OCR 做同条件性能/CPU/功耗对照，没有真机电量证据，没有证明主要耗时来自哪段系统内部实现。不能声称更省电、更快或达到产品 P95。日志中也观察到非目标窗口事件导致重读；事件调度仍有优化空间。京东、登录态、详情、购物车未验收。

## Chrome 插件开发版（2026-10-08）

用户授权 CC 开发 Chrome 插件。实际 Claude Code Opus 5.5 实现独立 `chrome-extension/`，Codex 独立阅读、运行与补充浏览器测试。原生 JavaScript + Manifest V3，不改 Android 方案；29 个既有 Android 源文件哈希均未变化。

行为：每张能确定主价的人民币商品卡片显示一个「10年≈金额」，默认 1.5 倍，可设置 1–10。默认没有网站权限；在 popup 开启当前站点时申请该主机权限，后台注册动态内容脚本并核对实际运行状态。网页 MutationObserver 驱动改价/增删更新，Shadow DOM 标签不拦截点击，遮挡/歧义/放不下时不画并给计数。不联网、不读 Cookie、不读取图片像素。纯文本读价也不等于支持全部网页结构。
